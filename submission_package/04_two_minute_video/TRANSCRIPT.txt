This is GradeSense, an AI assessment system that marks student answer papers. You give it three PDFs — a question paper, a marking scheme with the model answers, and a student's answer script — and it marks that script against the scheme point by point, shows you the exact sentence on the page that earned or lost each mark, and exports an annotated PDF you can hand back to the student. Architecturally it's a Next.js 16 modular monolith: route handlers and an Express API that only validate requests with Zod, a service layer that owns the database transactions, and two pipelines underneath. The PDF pipeline extracts text with PDF.js plus every text item's position on the page; the LLM pipeline sends the flattened rubric and the student's text to Gemma and Gemini through an ordered provider chain, recording which model actually answered. The core decision is that the model interprets and the code calculates: the model classifies each rubric point and writes the feedback, but it never computes the total — its output passes a Zod schema, then a bounds and rubric-ID check, and only then does the server sum the marks itself. Evidence works the same way: the model quotes a sentence rather than guessing coordinates, and we fuzzy-match that quote against the positioned text to find the box, because a box in the wrong place is worse than no box. Here's a live run. Three PDFs in; extracting, grading, annotating. This student's economics answer reasons correctly but reads the equilibrium off the wrong row — the grader docks that one point, quotes the sentence containing the error, and leaves the surrounding marks intact. I can drag the box or rewrite the note without re-running grading, then export. Behind it: 176 automated tests, and a twelve-script evaluation set I hand-marked first. Two honest limits — photographed handwriting is refused rather than OCR'd, and diagram questions are marked from the diagram's text labels, not the drawing itself.
